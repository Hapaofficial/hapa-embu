Implement HAPA Public Professional Profile — Sprint 3A.

ARCHITECTURE RULE

The verified Professional application and the editable public Professional profile are two completely separate entities.

Verified application:
- identity and document verification,
- private,
- locked after approval,
- controlled by Owner.

Public Professional profile:
- public service offering,
- editable continuously by the approved user,
- contains no private identity data or private documents.

GOAL

An approved Professional user must be able to create, publish and continuously update a public service profile without reopening or changing the verified identity application.

1. ELIGIBILITY

Only a user satisfying all conditions may create or publish a Professional profile:

- role='customer'
- status='active'
- capabilities.professional=true
- Professional application status='approved'

Pending, rejected, corrections_requested and suspended users may not publish a public Professional profile.

2. APPROVED PROFESSIONAL SCREEN

Replace the current approved-only screen with:

Professional role active

Primary actions:
- Manage professional profile
- View public profile
- Pause profile / Reactivate profile

Secondary action:
- View verified application

The verified application remains read-only.

- phone visibility

5. LOCKED VERIFIED FIELDS

The public profile must never allow changes to:

- legal name
- national ID or passport number
- private verified documents
- Owner review notes
- application status
- capability flags
- role
- verified profession category

The profession category must be copied from the approved application and remain locked.

Display:

“Contact HAPA support to request a change to your verified profession category.”

Do not build the category-change workflow in this sprint.

6. PUBLIC IMAGE STORAGE

Public portfolio images must NOT use the private-document bucket or private_documents table.

Create a separate public-media storage abstraction.

Use environment variables equivalent to:

PUBLIC_MEDIA_STORAGE_MODE=local|s3
PUBLIC_MEDIA_S3_BUCKET
PUBLIC_MEDIA_S3_ENDPOINT
PUBLIC_MEDIA_S3_REGION
PUBLIC_MEDIA_S3_ACCESS_KEY_ID
PUBLIC_MEDIA_S3_SECRET_ACCESS_KEY

For local development:
- store outside source files,
- serve only sanitized public media.

For staging:
- use a separate staging public-media bucket.

Do not use:
- hapa-private-documents
- hapa-staging-private-documents

Do not expose any private-document object as portfolio content.

7. IMAGE SECURITY

All public profile and portfolio images must:

- upload through multipart/form-data,
- be validated by actual file bytes,
- accept JPEG, PNG and WebP only,
- reject SVG and malformed files,
- be processed with sharp,
- auto-orient,
- strip EXIF and GPS,
- resize to safe dimensions,
- calculate SHA-256,
- use generated PII-free object keys.

Allow:

- Take a photo
- Choose from gallery
- upload progress
- preview
- replace
- remove
- reorder

Maximum:
- 1 public profile photo
- 12 portfolio/work photos
