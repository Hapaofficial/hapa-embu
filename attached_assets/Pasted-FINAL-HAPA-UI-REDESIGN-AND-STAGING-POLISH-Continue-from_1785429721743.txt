==================================================
1. DESIGN DIRECTION
==================================================

Replace the current heavy all-dark interface with a modern, professional, light-first HAPA design.

The product should look like a trustworthy modern marketplace, not a technical administration panel.

Use a consistent design system based on CSS variables.

Required base palette:

--hapa-background: #F5F7FA;
--hapa-surface: #FFFFFF;
--hapa-surface-muted: #F8FAFC;
--hapa-header: #101C2C;
--hapa-primary: #F5A623;
--hapa-primary-hover: #DE8F12;
--hapa-text: #172033;
--hapa-text-muted: #667085;
--hapa-border: #E1E6ED;
--hapa-success: #198754;
--hapa-warning: #E59A00;
--hapa-danger: #C63C49;
--hapa-info: #2563EB;

The exact shades may be adjusted slightly only when needed for accessibility, contrast or visual consistency.

Use:

- dark navy for the main header and navigation
- white cards and forms
- light grey page background
- orange only for primary actions and active navigation
- green only for approval, verified and success states
- red only for destructive, suspension or deletion actions
- neutral grey for secondary controls
- blue only for informational links where appropriate

Do not use orange on every button.
Do not use red for ordinary navigation.
Do not leave large empty dark areas.

Default launch appearance must be the new light theme.

Do not add a theme switch in this task unless it can be done safely without increasing scope. A future optional dark mode must not delay this redesign.

6. OWNER USER ACTION SAFETY
==================================================

On the active customer detail page, the current actions include:

- Reject
- Block

Inspect the actual backend behavior.

Do not show an ambiguous “Reject” action for an already active and approved customer unless there is a genuinely pending account-access decision.

Either:

- hide the action when not applicable, or
- rename it to an exact description of the real operation

Rename:

- Block → Suspend account

For suspended accounts show:

- Reactivate account

Every restrictive or destructive action must display a confirmation modal containing:

- customer name
- exact action
- consequence
- Cancel button
- explicit confirmation button

General account suspension must not:

- remove customer role
- delete approved capabilities
- alter verified categories
- delete verification history
- silently remove public content history

Suspension may hide public content as required, but restoration must preserve prior records.
