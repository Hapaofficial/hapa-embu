## PART 1 — PROFESSIONAL IN-APP RECEIPT

Replace the browser `alert()` currently used by `rdReceipt()` in `public/index.html`.

Create a polished HAPA receipt modal consistent with the existing design system:

* Navy HAPA header
* HAPA logo/wordmark
* “Official ride receipt”
* Green `PAID` status
* Clear route presentation
* Professional spacing and typography
* Responsive desktop and mobile layouts

Display only customer-facing information:

* Receipt reference
* Date and time in `Africa/Nairobi`
* Pickup
* Destination
* Driver display name
* Vehicle make/model
* Vehicle registration
* Distance in kilometres
* Duration in minutes
* Payment method: Cash or M-Pesa
* Payment reference when available
* Fare breakdown:

  * Base fare
  * Booking fee
  * Distance charge
  * Time charge
  * Waiting charge when applicable
* Final total

Money formatting must always use:

`KES 346.13`

Use thousands separators and exactly two decimal places.

Never expose:

* Platform commission
* Driver earnings
* Internal user IDs
* Rate-card IDs
* Database IDs
* Internal payment mode
* Debug information
* Raw API responses

Every server-supplied value must be escaped before insertion into HTML.

## PART 2 — RECEIPT INTERACTIONS

Change the receipt function to:

`rdReceipt(rideId = rdState.rideId)`

This must allow receipts to be opened from both:

* The active completed ride card
* Historical closed rides

Provide these actions:

### Download PDF

Do not download a `.txt` or `.html` file.

Add an authenticated endpoint:

`GET /api/rides/:id/receipt.pdf`

Requirements:

* Reuse the existing ride authorization and receipt record.
* Only authorized ride participants and currently permitted owner/support access may download it.
* An unrelated user must receive `403`.
* An unauthenticated request must receive `401`.
* A ride without a finalized receipt must receive `404`.
* Generate a clean, branded PDF containing the same customer-facing receipt information shown in the modal.
* Do not include commission, driver earnings or internal accounting fields.
* Return:

  * `Content-Type: application/pdf`
  * `Content-Disposition: attachment; filename="HAPA-Receipt-<REFERENCE>.pdf"`
  * `Cache-Control: private, no-store`
* Sanitize the filename.
* Do not create public receipt URLs.
* Do not save additional PDF copies in the database or public storage.
* Add the PDF dependency properly to `package.json`, `pnpm-lock.yaml` and `package-lock.json` if required by the repository.
* Preserve the existing Render build process.

### Share

* Prefer sharing the generated PDF file through the native Web Share API when file sharing is supported.
* Otherwise share a clean text version of the receipt.
* If native sharing is unavailable, copy the text receipt to the clipboard.
* Never create a public receipt link.
* Show success/failure feedback inside the modal.
* User cancellation of the native share sheet must not display an error.

### Close

The modal must close through:

* Close button
* X button
* Escape key
* Backdrop click

Accessibility requirements:

* `role="dialog"`
* `aria-modal="true"`
* Proper accessible title
* Move focus into the modal
* Trap Tab/Shift+Tab focus inside the modal
* Restore focus to the original Receipt button after closing
* Prevent background scrolling while open
* Restore scrolling after closing
* Minimum 44px touch targets
* Visible keyboard focus
* Do not rely only on colour to communicate status

## PART 3 — LOADING AND ERROR STATES

Receipt loading must be professional:

* Prevent duplicate receipt requests.
* Disable the clicked Receipt button while loading.

* Display API errors in an inline HAPA notice.
* Do not use browser alerts for receipt loading, sharing, downloading or errors.

## PART 4 — IMMEDIATE RECENT RIDES

Currently a completed ride does not appear in `Recent rides` until the customer presses `Done`.

Fix this.

When `rdRefresh()` receives:

* `closed`
* `rider_cancelled`
* `driver_cancelled`

it must immediately refresh `Recent rides`.

Important behavior:

* Keep the terminal active-ride card visible.
* The rider must still be able to rate a closed trip and open its receipt.
* Do not automatically dismiss the active card.
* Do not require `Done` before adding the ride to history.
* Do not create duplicate history entries.
* Do not create recursive refresh loops.
* A failed history refresh must not clear the active ride.

Update `rdLoadHistory()`:

* Show the five latest terminal rides.
* Use `completed_at` when available, otherwise `created_at`.
* Format dates using `Africa/Nairobi`.
* Format fares with exactly two decimals.
* Show a clear status label.
* Only `closed` rides with finalized payment may show the `Receipt` button.
* Cancelled rides must appear in history but must not show a Receipt button.
* The historical Receipt button must call `rdReceipt(r.id)`.
